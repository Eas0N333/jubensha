# 云服务器部署指南

从零到「朋友能打开链接玩上」大概 15 分钟。

**一句话版本**：Node 22 起一个进程 + nginx 反代做 HTTPS + 开 `ACCESS_CODE`。
如果朋友的网络环境杂（手机热点、公司网、跨运营商），**再加一台 coturn**，否则语音会时通时不通。

---

## 0. 先想清楚一件事：语音要不要 TURN

语音走的是 WebRTC 点对点，服务器只转发信令。浏览器之间要直接连上，就得靠 ICE 打洞：

| 场景 | 只配 STUN（默认） | 配了 TURN |
| --- | --- | --- |
| 同一局域网 | ✅ | ✅ |
| 家宽对家宽（NAT 不严格） | ✅ 大多数可以 | ✅ |
| 手机 4G/5G、公司网、校园网 | ❌ 大概率连不上 | ✅ |
| 跨运营商 | ⚠️ 经常失败 | ✅ |

**不配 TURN 的表现**：文字聊天、剧本、搜证全部正常，只有语音按钮点了之后对方显示「连接中…」一直转圈，最后没声音。排查起来很费时间，所以宁可一开始就配。

TURN 会消耗服务器流量（语音转发），一台 1 核 1G 的小机器带 3–5 个人一局是完全够的（语音约 40 kbps/人）。

> 想先跑起来看看效果，可以先跳过 TURN，用同一间屋子里的两台设备试。确认没问题再配 TURN 给远程的朋友。

---

## 1. 起服务

### 方式 0：一键脚本（最短路径）

代码推到 GitHub 之后，服务器上就三条命令：

```bash
sudo apt update && sudo apt install -y git
git clone https://github.com/你的用户名/online-story.git /opt/online-story
cd /opt/online-story && sudo bash deploy/install.sh
```

脚本会问你三件事——**域名**（留空就按 服务器IP:端口 + 自签证书 走）、**通行码**（建议设）、
**TURN 地址**（留空则只配 STUN，见上面第 0 节）。然后它自己完成：检查 Node 版本 → 装生产依赖 →
写 `.env`（权限 600）→ 装 systemd 服务并启动 → 有域名就配 nginx 并按需申请 Let's Encrypt 证书 →
跑一次健康检查 → 打印访问地址和后续命令。

也可以无人值守（配置全走环境变量）：

```bash
sudo DOMAIN=game.example.com ACCESS_CODE=你的口令      TURN_URL=turn:你的公网IP:3478 TURN_USER=u TURN_PASS=p      bash deploy/install.sh --yes
```

想先看它要干什么，加 `--dry-run`，只会打印命令、不改动系统。

以后更新：

```bash
cd /opt/online-story && sudo bash deploy/update.sh
```

下面两种方式适合想自己控制细节的情况。

### 方式 A：Docker（推荐）

```bash
# 服务器上：装 docker 与 compose 插件（略）
git clone https://github.com/你的用户名/online-story.git online-story && cd online-story
cp .env.example .env
vim .env          # 至少设一个 ACCESS_CODE
docker compose up -d
docker compose logs -f        # 看到「线上剧本杀已开服」就成了
```

访问 `http://服务器IP:5178` 应该已经能开房了（此时还没有 HTTPS，语音会失败，下一步解决）。

### 方式 B：裸机 + systemd

```bash
sudo apt update && sudo apt install -y nodejs npm nginx
sudo mkdir -p /opt/online-story && sudo chown $USER /opt/online-story
# 把项目传上去（git clone / scp / rsync 都行）
cd /opt/online-story && npm ci --omit=dev
cp .env.example .env && vim .env

sudo cp deploy/game.service /etc/systemd/system/online-story.service
sudo useradd -r -s /usr/sbin/nologin www-data 2>/dev/null || true
sudo chown -R www-data:www-data /opt/online-story
sudo systemctl daemon-reload && sudo systemctl enable --now online-story
journalctl -u online-story -f
```

## 2. 配 HTTPS（语音的必要条件）

浏览器只在 **HTTPS** 或 **localhost** 下允许网页拿麦克风。所以要让远程的朋友用语音，必须上 TLS。

### 有域名

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo cp deploy/nginx.conf.example /etc/nginx/sites-available/online-story
sudo vim /etc/nginx/sites-available/online-story   # 把 game.example.com 换成你的域名
sudo ln -s /etc/nginx/sites-available/online-story /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d game.example.com           # 自动写证书 + 加 301 跳转
```

然后回到 `.env`，打开 `TRUST_PROXY=1`，`PUBLIC_URL=https://game.example.com`，重启服务。

> **nginx 配置里最容易漏的一行**是 `proxy_set_header Upgrade $http_upgrade;`
> 和 `proxy_set_header Connection $connection_upgrade;`。漏了的话 Socket.IO 会退回轮询，
> 表现是「能动但很卡、语音信令偶尔丢」。示例里已经写好了。

### 没有域名（IP 直连）

自签证书模式，浏览器会拦一次警告：

```bash
cd /opt/online-story
sudo -u www-data HTTPS=1 node server/index.js
# 首次会自动生成证书到 .certs/
```

服务器端可以直接在 `.env` 里写 `HTTPS=1`。用 IP 访问时浏览器会提示「不安全」，
点「高级 → 继续前往」即可（自签证书里已经包含本机所有网卡 IP，包括公网 IP）。

## 3. 配 TURN（让语音在各种网络下都能通）

```bash
sudo apt install -y coturn
sudo cp deploy/coturn.conf.example /etc/turnserver.conf
sudo vim /etc/turnserver.conf
#   改 external-ip = 你的公网IP
#   改 user=用户名:密码
sudo vim /etc/default/coturn      # 打开 TURN_SERVER_ENABLED=1
sudo systemctl enable --now coturn

# 云服务器安全组 / 防火墙放行：
#   3478/udp  3478/tcp
#   49160-49200/udp      （示例配置里的中转端口范围）
```

然后在 `.env` 里填：

```env
TURN_URL=turn:你的公网IP:3478
TURN_USER=你在coturn里设的用户名
TURN_PASS=你在coturn里设的密码
```

重启服务。启动 banner 上那行 `TURN` 会从「未配置」变成「已配置」。

**验证 TURN 有没有生效**：浏览器打开 `https://你的域名/api/rtc-config`，
应该能看到 `turn:...` 那一条。然后两个人开麦，在浏览器地址栏输入
`chrome://webrtc-internals` 看 `selectedCandidatePair`——如果类型是 `relay`，说明正在走 TURN。

## 4. 公网必做：设通行码

默认任何人拿到地址都能开房。开一堆空房间会占内存，也会有人在你的服务器上白玩。

```env
ACCESS_CODE=换成你自己的口令
```

设了之后，首页会多出一个「通行码」输入框，建房和加入都要带上。把这个口令和你发出去的房号一起给朋友就行（浏览器会记住，填一次就够）。

## 5. 完整的环境变量

全部可选，不设就是默认值。参考 `.env.example`。

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `PORT` | `5178` | 监听端口 |
| `HOST_BIND` | `0.0.0.0` | 绑定地址。只给本机用设 `127.0.0.1` |
| `TRUST_PROXY` | 关 | 放在 nginx / 云负载均衡后面时设 `1`，日志才拿得到真实访客 IP |
| `HTTPS` | 关 | `1` 用自签证书起 HTTPS；有 nginx 就别开 |
| `ACCESS_CODE` | 空 | 通行码，**公网建议设置** |
| `PUBLIC_URL` | 空 | 只影响启动时打印的那行地址 |
| `STUN_URL` | 谷歌公共 STUN | 逗号分隔多个 |
| `TURN_URL` | 空 | 逗号分隔多个，例如 `turn:1.2.3.4:3478` |
| `TURN_USER` / `TURN_PASS` | 空 | coturn 的长期凭据 |

## 6. 部署后自查清单

> 用一键脚本的话，前两项脚本已经跑过了，从第三项开始看。

- [ ] `curl http://127.0.0.1:5178/api/health` 返回 `{"ok":true,...}`
- [ ] 启动 banner 里 `通行码` 是「已开启」
- [ ] `curl https://你的域名/api/rtc-config` 能看到 `turn:` 那一条
- [ ] 用 `https://` 打开首页，地址栏是小锁（或已点过「继续前往」）
- [ ] 点右上角「开麦」，浏览器弹出麦克风授权（没弹说明不是 HTTPS）
- [ ] 两个人手机（流量，不是家里 WiFi）分别进同一个房间，开麦能互相听到
- [ ] 手机浏览器上翻一下剧本、点一下地图，界面能用

## 7. 需要知道的限制

- **房间在内存里，服务重启就没了。** 别在有人玩的时候重启；`docker compose` 已经配了 `restart: unless-stopped`。
- **只能单实例。** 房间状态在进程内存里，要开多台机器得先接 socket.io 的 Redis adapter（本项目没做）。一台 1 核 2G 的小机器同时带几局完全够用。
- **没有账号系统。** 靠通行码 + 四位数房号。房号是从 32 个字符里随机四位，不认识房号基本撞不进来。
- **静态资源带版本指纹**（`?v=<mtime>`），改完代码重启，玩家刷新就能看到新版，不会吃到旧缓存。
- **语音是网状直连**，人越多每个人的上行越高。五六个人用浏览器开麦没问题；再多要考虑换 SFU。
- **`/api/art/*` 是即时生成的 SVG**，没做服务端缓存。真的担心性能可以给它加一层 CDN，但一局游戏也就拉几十张，无所谓。

## 8. 常用运维命令

```bash
# 看日志
docker compose logs -f --tail=100
journalctl -u online-story -f

# 重启（会结束所有进行中的房间）
docker compose restart
sudo systemctl restart online-story

# 更新代码
git pull && docker compose up -d --build
git pull && npm ci --omit=dev && sudo systemctl restart online-story

# 看谁连着
ss -tnp | grep :5178 | wc -l

# TURN 日志
journalctl -u coturn -f
```
