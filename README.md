## 快速开始

需要 Node.js 18 以上。

```bash
npm install
npm start
```

打开终端里打印的地址（默认 `http://localhost:5178`），一个人点「开一间房」，把四位数房号发给朋友，其他人填房号和昵称点「加入」。

**要开语音就得用 HTTPS** —— 浏览器只在 `localhost` 或 HTTPS 下允许网页拿麦克风。跨设备玩请用：

```bash
npm run https
```

首次运行会在 `.certs/` 下自动生成一张自签证书（已包含本机局域网 IP）。浏览器会拦一次，点「高级 → 继续前往」即可。用 `npm start` 也能玩，只是语音按钮在非 localhost 环境下会失败，文字聊天不受影响。

其他命令：

```bash
npm run dev      # 改代码自动重启
npm run check    # 语法体检（服务器 + 前端所有文件）
npm test         # 三本剧本各跑一遍协议层端到端自测（共 212 项断言）
npm run test:studio   # 只跑三人本
npm run test:steamer  # 只跑四人本
npm run test:wuyin    # 只跑五人本
```

### 传到 GitHub，再在服务器上一键部署

仓库已经初始化好并做好了首次提交（`.env` 和 `.certs` 都在 `.gitignore` 里，不会被提交上去）。
你在本地建一个空仓库，然后：

仓库地址：**https://github.com/Eas0N333/jubensha**

```bash
git clone https://github.com/Eas0N333/jubensha.git
```

> 改完代码推回自己的仓库：
> ```bash
> cd "F:/workplace/online story"
> git add -A && git commit -m "说明"
> git push
> ```
> 注意：**这台机器直连 github.com 是不通的**（要经本地代理 127.0.0.1:7897）。
> 如果 push 报 `Could not connect to server`，加上代理再推：
> ```bash
> git -c http.proxy=http://127.0.0.1:7897 push
> ```
> 想一劳永逸（只对这个仓库生效）：
> ```bash
> git config --local http.proxy http://127.0.0.1:7897
> ```

然后在服务器上：

```bash
sudo apt update && sudo apt install -y git
sudo mkdir -p /opt/online-story && sudo chown $USER /opt/online-story
git clone https://github.com/Eas0N333/jubensha.git /opt/online-story
cd /opt/online-story
sudo bash deploy/install.sh
```

Docker 路线则是：

```bash
cd /opt/online-story
sudo bash deploy/docker-mirror.sh    # 国内服务器先配镜像加速，否则拉不动 node:22-alpine
cp .env.example .env && vim .env     # 至少设 ACCESS_CODE
docker compose up -d
```

脚本会依次问你：域名（可留空）、通行码、TURN 地址，然后自动完成装依赖、写 `.env`、装 systemd 服务、
配 nginx + 申请证书。跑完会打印访问地址。

以后更新就一条命令：

```bash
cd /opt/online-story && sudo bash deploy/update.sh
```

想先看看脚本要干什么，可以干跑一遍（不改动系统）：

```bash
sudo bash deploy/install.sh --dry-run
```

### 部署到云服务器

代码已经按可部署的样子收拾过了：配置全走环境变量（`.env.example` 有全部说明）、支持 `ACCESS_CODE` 通行码、收到 `SIGTERM` 会优雅退出、WebRTC 的 STUN/TURN 由服务端下发给浏览器（可以自己配 coturn）。

```bash
cp .env.example .env && vim .env    # 至少设 ACCESS_CODE
docker compose up -d
```

> 国内服务器如果卡在拉 `node:22-alpine` 上（`dial tcp ...: i/o timeout`），先跑
> `sudo bash deploy/docker-mirror.sh` —— 它会探测可用的镜像站、写好配置并实测拉取。

完整步骤（nginx 反代 + Let's Encrypt 证书 + coturn）见 **[docs/部署指南.md](docs/部署指南.md)**。

**部署前必须知道的两件事：**

1. **语音需要 HTTPS。** 浏览器只在 HTTPS 或 localhost 下允许网页拿麦克风。
2. **只配 STUN 的话，一部分玩家连不上语音。** 手机流量、公司网这类严格 NAT 环境下打洞会失败——表现是文字一切正常、语音一直「连接中…」。给这类朋友玩，就照部署指南配一台 coturn。

## 怎么玩

人数按剧本走（三人本 3 人，五人本 5 人）。房主就是主持人，负责推进阶段，同时也是场上玩家。

| 阶段 | 你在做什么 |
| --- | --- |
| 序章 · 雨夜 | 读第一章，轮流用一句话介绍自己是谁、和死者的关系 |
| 节点 · 山庄探索 | 点开平面图上的每个房间，熟悉格局，拿到三条环境线索 |
| 第一轮搜证 | 每人 2 点行动力，点击地图上的房间抽取线索卡 |
| 第一轮讨论 | 自由讨论，随时翻剧本和线索 |
| 节点 · 书房保险柜 | 四位密码锁，密码藏在某个人的记忆里 |
| 第二轮搜证 | 再给 2 点行动力，去第一轮没人去过的地方 |
| 节点 · 苏漾的出诊箱 | 六瓶试剂配六个标签，连错了会断 |
| 第二轮讨论 | 开始互相质证 |
| 节点 · 拼合时间线 | 把八张事件卡按发生顺序排好 |
| 节点 · 修复照片 | 3×3 滑块拼图，复原一张烧焦的全家福 |
| 最终陈述 | 每人最后一分钟 |
| 指认凶手 | 多数决 |
| 真相揭晓 | 完整叙事、推理链、动机、尾声、本局积分 |

三人本和四人本的流程短一截（12 个阶段）。三人本的节点是：照相馆探索 → 暗房储物柜密码 → **暗房显影** → 拼合当晚时间线；四人本是：船上探索 → 死者的皮箱密码 → 药箱验伤连线 → 拼合当晚时间线。

### 暗房显影（三人本专属节点）

把一卷底片按正确的工序冲出来：三只药盘（显影液 / 停显液 / 定影液）要点对顺序，还要按工作手册上的参数定对显影时间。顺序错了这一卷就废了（进度清空重来）；顺序对但时间错，只提示时间，工序不会白排。冲出来的那张照片，是整本剧本的钥匙。

### 搜证是怎么算的

线索是有限的，但**不会让你因为运气差而破不了案**：

- **每个地点第一次被搜，必定出关键线索。** 每个房间的线索池里，「◆ 关键线索」永远排在抽取顺序的最前面，气氛类线索排在后面。所以你翻一个地方，第一张一定是有用的东西——不会出现"决定性证据刚好被压在池底、整局都没翻出来"。
- **地图上标着还剩什么。** 每个房间显示「还剩 N 张线索　◆ K」，有 ◆ 的房间左上角钉一个金色小菱形；图例汇总「楼里还剩 X 张，其中 ◆ 关键线索 Y 张」。
- **第二轮开始会点名。** 进入第二轮搜证时，如果有人还没翻出来的关键线索，会直接告诉你「还有 3 张关键线索，分别在：库房、二楼卧室」。这是主持人该做的事，不给这个提示很容易整局都碰不到定案的那张。
- **行动力够翻完。** 每轮每人 3 点行动力、共两轮。三个人 18 次 / 17 张，四个人 24 次 / 20 张，五个人 30 次 / 32 张——**只要分头搜，基本能翻完**。真正会浪费行动力的是两个人搜了同一个房间，这是策略问题，不是运气问题。
- **◆ 只标真正定案的线索**，占比 40% 左右。早期版本把 80% 的线索都标了「关键」，那等于没标。

### 几个规则细节

- **剧本是私密的。** 服务端按玩家身份裁剪后才下发，任何人拿不到别人的本子——包括浏览器调试面板里也看不到。剧本分四章，随阶段逐步解锁。
- **阅读视图**：左侧「我的剧本」是一张封面卡，点开就是一本可以翻的小册子——目录、纸页、翻页，`←` `→` 翻，`Esc` 合上。第一页固定是**你的任务**，后面才是各章正文。没解锁的章节在目录里显示会在哪个阶段解锁。
- **任务写得足够具体**：每个角色都有一份任务页——你是谁、你要什么、怎样算赢、你必须瞒住哪几件事、以及**按阶段列出该做什么**（当前阶段那一条会自动高亮，做过的打勾）。左侧栏也有一份任务速览，讨论到一半不用翻本子就能瞄一眼。
- **线索是有限的。** 每个房间的线索卡抽一张少一张，地图上会显示还剩几张。谁先搜谁先得。
- **公开线索**会把卡直接拍到公共线索区，全房间永久可见，也是全场最主要的信息交换方式。除此之外还能**私下把线索交给某个人**，用来换情报。右侧面板分「我的线索 / 公开线索」两页。
- **行动力**每轮重置为 2 点，用于搜证，不能攒。
- **语音**：开麦之后，玩家名字右边会出现一个圆点——灰色是没开麦，绿色是开麦，说话时会亮起来并轻轻脉动。大厅、讨论页和底部语音条上都有这个点。
- **投票**不能投自己。**所有人都投完会自动揭晓**（等 2.5 秒让大家看清票型）；如果有人迟迟不投，房主可以手动提前揭晓，但会先弹一次确认。平票不算指认成功。
- **无人扮演的角色**转成主持人手册后，也可以在阅读视图里逐章翻阅（目录里单独分组）。
- 人不满也能开：没被扮演的角色会转成**主持人手册**，只有房主能看，需要房主替他们提供信息。两个人就能开局（适合先自己跑一遍熟悉流程）。

### 主持人面板

房主点右上角「主持人面板」，可以看到：当前进度概览（阶段 / 已公开线索 / 解谜进度 / 已投票 / 无主角色）、按顺序列出的全部 13 个阶段（当前阶段高亮、已过的阶段变暗，每行带该阶段的提示），以及所有无人扮演的角色。

点任意阶段可以直接跳过去——回头重进某个阶段不会清掉已经搜到的线索和解开的谜题。

### 技术选择

- **前端零构建**：原生 ES 模块 + 一个 `<script type="module">`，改完刷新就生效，没有打包步骤。
- **插画零素材**：所有线索配图（匕首、怀表、封蜡上的针孔、暗房的红灯、双反相机、铜手炉、铁撬棍……共 41 张）都是服务端按需生成的 SVG，离线可用，也不会有版权问题。
- **语音是 WebRTC 网状连接**，Socket.IO 只负责转发信令与游戏状态，音频不经过服务器。后来开麦的人主动发起 offer，避免双方同时 offer 的冲突。
- **服务端权威**：谜题答案、别人的剧本、未公开的线索都只存在服务端。解谜结果由服务端校验（拼图除外，它是合作玩法，由客户端判定）。

## 想加一本剧本？

照着 `server/data/studio.js` 写一个新文件，然后在 `server/data/registry.js` 里 import 进来、加进 `scenarios` 就行。一本剧本一个文件装下全部内容：`cast`（角色与剧本、任务简报）、`rooms`（搜证地点与线索卡）、`nodes`（解谜节点）、`phases`（阶段流程）、`truth`（真相与推理链）。前端不用改——首页的剧本选择器、地图、剧本阅读器、主持人面板全部是按数据渲染的。

房间坐标只要落在 `mapView` 的 `960 × 600` 里就行：楼体轮廓、回廊带、门口那条街都是按房间的包围盒自动算的，不会压到房间上。

线索配图用 `art` 字段指定，取值是 `server/data/art.js` 里的函数名；没有的图会退回默认底纹。

## 已知限制

- 语音走 P2P 网状连接。服务器默认只给公共 STUN，**跨公网遇到严格 NAT 需要自建 TURN**（配 `TURN_URL` 即可，见部署指南）。
- 拼图节点由客户端判定完成，理论上可以绕过——合作游戏，不作弊对所有人都有好处。
- 房间是纯内存的，进程重启数据就没了；也没有账号系统（公网部署靠 `ACCESS_CODE` 挡一下）。
- 只能单实例运行：房间状态在进程内存里，要多机需要自己接 socket.io 的 Redis adapter。
- 前端资源带 `?v=<mtime>` 指纹，改完文件刷新就能看到效果，不会被浏览器缓存坑到。
- 界面按桌面宽度设计，窄屏会折叠成单列，手机上的体验不算好。
